# Per-binary size limits in bytes, checked by `make size`.
#
# These are NOT section 10.2's tier budget. That document sets embedded at 1 MB
# and calls it a "budget to validate, not a measurement". (It also set nano at
# 400 KB; decision 0021 dropped that tier.)
# What is built today is the full tier: every feature compiled in, and two
# separate static binaries that each link most of the workspace. Meeting the
# embedded budget is M5's job, through the build profiles that compile the DSL
# compiler, the client and the adapters out -- and probably through making
# `ncfg` and `netcfgd` one multi-call binary, since duplicating the shared
# crates is most of what is being paid for here.
#
# Measured as **total installed size**, not per binary. What a 16 MB router
# cares about is how much flash the install takes; a per-binary limit would call
# merging two binaries a regression when it saves a megabyte of flash. The
# per-binary numbers are still printed, because "which one grew?" is the next
# question -- but only the total is a gate.
#
# What this file does instead is ratchet. A limit is the last measured size
# plus a small tolerance, so ordinary growth fails the build and raising a
# number is a deliberate, reviewable edit rather than something that happens
# quietly. Constraint 8's point is not the specific figure, it is that nobody
# gets to drift upward without saying so.
#
# Tolerance covers compiler-version noise; a real feature will exceed it.
tolerance_percent 3

# M3, the supplicant and the wifi config syntax. netcfgd grew 86 KB and ncfg
# 37 KB across two steps: the control-socket client and the wireless request
# handlers, then the compiler learning `network` and `device.wifi` blocks --
# which both binaries carry, since `ncfg` compiles the config itself. Plus
# serde's generated code for the new protocol types.
#
# No new dependency in any of it. The whole increase is code that was written
# rather than pulled in, which is what constraint 3 was protecting.
#
# Recorded at the measured size rather than left to ride the tolerance: the 3%
# is for compiler-version noise, and spending it on a real feature means the
# next real feature fails the gate for the wrong reason.
#
# Then wired 802.1X: netcfgd-apply gained the supplicant client, because
# starting a supplicant and filling it is one action rather than two. ncfg took
# the larger share (+45 KB against netcfgd's +12 KB) since it links the
# executor for `--oneshot` and did not already carry the supplicant -- `ncfg
# apply` really can bring up an 802.1X port, so the code has to be there.
#
# Then the M4 model gaps: policy routing rules, access points, ethtool
# settings, IPv6 tokens and MAC randomization -- types, serde and compiler
# lowering for five features of which one is implemented. netcfgd +61 KB, ncfg
# +29 KB, and most of it is serde's generated code for the new types rather
# than logic. That is the cost of the freeze: three of these produce no
# behaviour today and are carried anyway, because adding them after M4 is a
# major version bump.
#
# Then M4 link types: bond, vxlan and veth creation, per-kind attributes for
# all of them, and the member-list expansion. +12 KB each, which is what
# actual netlink encoding costs when the types already exist.
#
# Then generic netlink and WireGuard: the family resolver, the wg encoder and
# reader, the base64 key type, and the compiler lowering. +25 KB and +29 KB.
# The genl half is small; most of this is WireGuard, and both binaries carry it
# because `ncfg apply --oneshot` configures a tunnel as readily as the daemon.
#
# Then prefix delegation: the arithmetic, the observed delegation list, the
# DHCPv6 client hook and the planner resolution. +20 KB and +16 KB.
#
# Then the five scope-capable DNS backends: openresolv, resolved, dnsmasq,
# unbound and exec. +12 KB each -- the renderers are text and the delivery is
# a process spawn or a file write, so none of them is large.
#
# Then the pre-freeze format audit's findings: VRF, macvlan, the tunnel family
# (gre/gretap/ip6gre/ipip/sit/ip6tnl/geneve), tun/tap as schema-only, a
# spelling for parameterless kinds, and four more bridge parameters. +16 KB and
# +37 KB -- the tunnel encoding is three attribute families that disagree about
# numbering, which is most of it.
#
# Then PPPoE: the compiler, the planner treating a session as a prerequisite
# rather than a link, and the executor writing pppd's options file. +12 KB each.
# The binaries the gate sums. A name with no number is measured, not limited.
ncfg
netcfgd

# 1 MB is design section 10.2's embedded budget. The install is over it and
# that is M5's remaining size work -- the ratchet holds the line meanwhile.
#
# +37 KB for bridge VLANs: a second netlink dump under AF_BRIDGE, the setter,
# the range expansion, and the planner's per-port reconciliation.
#
# +8 KB for carrier-based switching: the preference field, metric resolution,
# and the DHCP client finally being told the metric the model always carried.
#
# +12 KB for detecting another daemon on the same interface.
#
# +72 KB for NAT and forwarding, which is the largest single step since M3 and
# was predicted: decision 0022 said "it costs size, and the budget is already
# over". It buys a whole second netlink protocol -- `NETLINK_NETFILTER`, its
# batched transaction framing, an nftables expression encoder and the reader
# that parses rules back -- plus the forwarding sysctls, two planner passes and
# two executor arms.
#
# This is the one to reach for first when the install has to shrink. 0022 and
# design section 10.3 already say so: a machine that is not a router should not
# be carrying an nftables encoder, and the table is self-contained enough to be
# an optional backend rather than something threaded through the model.
# +40 KB for root qdiscs: `struct tcmsg`, the set/reset/dump messages, the
# `cake` rate encoding, the scheduler enum and its config lowering, plus a
# planner pass and two executor arms. A third of what NAT cost, because this is
# rtnetlink on the socket netcfgd already holds rather than a second protocol
# -- which is the measured version of what decision 0023 predicted.
# +56 KB for ingress shaping: the `ifb` link kind, the ingress hook, a
# `matchall` classifier carrying a `mirred` redirect, the filter dump that
# reads it back, plus the compiler expansion that turns one config key into a
# synthesised device and a redirect. More than the qdisc work itself, because
# the filter is three levels of nesting to write and to parse.
