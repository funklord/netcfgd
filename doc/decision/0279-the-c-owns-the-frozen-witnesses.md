# 0279: the C owns the frozen witnesses

Status: accepted
Date: 2026-10-22
Milestone: M9; the C port

## What this decides

`make schema-bless` runs the C. The four files under `doc/schema/` are written
by `c/tests/`, not by `crates/`, and the Rust's four byte-comparison tests are
gone -- the rest of those files stays, because building every variant and
round-tripping it through serde in memory is still coverage of those types.

Decided by the copyright holder on 2026-10-22, after it was reported as the
last place 0266's shape survived.

## Why it had to move

0266 shipped the C. 0276 retired the Rust shim. Through both, **the witnesses
that define this project's wire forms were generated by the Rust**, and three
gates that read them were quietly pointed at the same program until this week
re-pointed them one at a time: `dbus_policy_gate.py` parsed the retired shim,
`linkage` read a binary nobody installs, `tier_table_gate.py` classified
requests out of `authorize.rs`.

The witnesses were the remaining instance, and the thing that made it
undeniable was a value rather than an argument. `ncfg_backend_kind_name`
answers for ten backend kinds; the tenth is an IPv4LL client for
`config = "link-local"`, appended for the C's own use, and
`c/include/ncfg/observed.h` says where it is appended that **"the Rust has no
word for it"**. So `doc/schema/observed.json` carried nine of ten, no bless
could have added the tenth, and the gate that noticed had to be given a named
exception -- which is the point at which a workaround becomes the design.

## What made the move cheap, and what would have made it expensive

**`ncfg_json_pretty` reproduces `serde_json::to_string_pretty` byte for
byte.** Measured before anything was changed: reading each witness through the
C's reader, writing it through the C's writer and laying it out gave
17,024 bytes identical for the observation and 118,079 identical for the
document. So this is a change of authorship and not a reformatting of every
schema -- which is what it would have been if the two layouts had differed by
a space.

**Three of the four are a round trip and one is a generator**, and the
distinction is worth stating because it is what this decision gives up:

    observed.json   read through the C's reader, written through its writer
    document.json   likewise
    plan.json       built from values in `plan_test.c`, exactly as
                    `crates/netcfgd-plan/tests/frozen.rs` built it
    socket.json     no blesser: edited by hand

The Rust built all four from code, so a field added to a struct appeared in
the witness on the next bless. Under a round trip it does not: the witness is
the sample set, and adding a sample is an edit somebody reviews. What catches
a field that should have appeared is the round trip itself -- a writer that
always emits a new member makes the comparison fail and names the byte -- and
the completeness gates, which is where the rest of this week's work went.

## The layout check this would have lost

The C's witness tests compared with whitespace removed, because the Rust wrote
pretty and the C writes compact. Under this decision that is not enough: a
witness whose indentation had drifted would have passed, where the Rust's byte
comparison caught it.

So each of the three now asserts the layout as well -- `ncfg_json_pretty` of
what it wrote, against the file, byte for byte. Seen to fail: one line
re-indented in `observed.json` makes the test say "the witness on disk is laid
out as this build lays one out: FAILED", and `make schema-bless` puts it back.

**A move that quietly weakened a check would have been a worse outcome than
not moving**, which is why that arm was built and exercised before this record
was written.

## What socket.json still does not have, named

No blesser. `c/tests/proto_test.c` reads every line, decodes it, re-encodes
every request, and asserts coverage counters over every request, response and
event kind -- so what the file MAY contain is held by the C, and what it DOES
contain is a diff somebody reviews. The Rust generated those 67 lines from
exhaustive matches, and reproducing that in C means building every message in
the protocol by hand, which is a piece of work rather than a line in this one.

Until it exists, a socket message added to the C has to be added to the
witness by hand, and `ledger_gate.py` is what says so: every request,
response and event kind the build names must have a line.
